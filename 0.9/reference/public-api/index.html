    Public API¶

    This page is the curated, workflow-organized reference for every public subsystem of AnyCode. Each section explains what a group of symbols is for, then generates signatures directly from the source docstrings. If you want a flat, exhaustive index instead, use the complete API inventory, which lists every name in anycode.__all__.

    Everything documented here is exported from the package root, so from anycode import AnyCode, TaskSpec, AgentConfig is always the supported import style. Treat internal submodule paths as private implementation detail. The compatibility policy defines additive patch releases, pre-1.0 breaking-change rules, and persisted-format guarantees.

    New here? Read the concepts first

    This reference lists signatures, not tutorials. For how the pieces fit together, start with the Concepts overview, then the How-to guides.

    How this page is organized¶

    The API is grouped the way you actually use it — from a first agent run out to production controls and the extension surface.

    • Core orchestration — the engine, agents, runners, and task specs.
    • Configuration models — typed settings for agents, teams, and the engine.
    • Result models — structured, auditable run output.
    • Teams and collaboration — messaging and shared memory.
    • Tools — define, register, secure, and execute typed tools.
    • Structured output — force a validated object.
    • Providers — model adapters and resilience.
    • Routing — send each task to the right model.
    • Handoff — delegate between agents mid-run.
    • Reflection — critique-and-revise loops.
    • Memory and RAG — persistence, retrieval, knowledge.
    • Context engineering — manage the context window.
    • Cost — price, track, and cap spend.
    • Guardrails — budgets, hooks, validators.
    • Verification and quality gates — block bad output.
    • Human-in-the-loop — approval gates.
